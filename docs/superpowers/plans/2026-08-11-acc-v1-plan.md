# Agent Crypto Control v1 Prototype Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working local prototype of the full spec: MCP-driven stablecoin control app where the agent authors and proposes, the app enforces policy and executes, and approval is a physical click in a browser window.

**Architecture:** Two processes. `src/main.ts` is the authoritative app (state, policy, execution, HTTP server + one-page UI on 127.0.0.1:4177). `src/mcp.ts` is a thin stdio MCP server spawned by the agent's MCP client; it proxies every call to the app over localhost HTTP and contains no state, no keys, and no approval path. Demo mode (default) runs on fixture balances and a synthetic quoter so the whole loop works offline and without keys; live mode reads real balances from public RPCs for configured addresses and quotes via NEAR Intents 1Click. Signing is stubbed behind a `Signer` interface (the auth step Karim does last).

**Tech Stack:** Node 24 (native TS type stripping, zero build step), `@modelcontextprotocol/sdk` + `zod` (only runtime deps), `node:test`, vanilla HTML/JS/canvas UI served by `node:http` with SSE.

## Global Constraints

- Erasable TS only: no enums, no namespaces, no parameter properties. Relative imports carry explicit `.ts` extensions. Verify with `npx tsc --noEmit` and by running.
- `src/types.ts` is the single source of truth for every cross-module signature. Do not redefine or drift from it; if it is wrong, stop and report rather than adapt around it.
- No new dependencies beyond `@modelcontextprotocol/sdk`, `zod`, dev-only `typescript`.
- The MCP process must contain no code path that can approve, refuse, dismiss, or execute a proposal, and no reference to the approval token or `/api/approve`.
- Exactly three policy outcomes: `allow`, `needs_approval`, `refuse`. No override path. Failures fail closed (unreadable policy refuses all writes; failed simulation refuses; unclassified assets count as freezable).
- Every tool call, proposal, approval, refusal, and execution appends one JSONL line to the audit log. The app never truncates it.
- No em or en dashes anywhere. No AI attribution. ASCII box-drawing allowed in UI.
- UI: system monospace stack, near-black background, green phosphor foreground, red only for pending approvals and refusals, no icons/shadows/rounded corners/gradients/animation (cursor blink and appending log lines excepted). Per spec, design skills are deliberately not used; `.design/brief.md` is the check target for ui-verify.
- HTTP server binds 127.0.0.1 only.
- External endpoints (verified 2026-08-11): 1Click `https://1click.chaindefuser.com/v0/tokens` and `POST /v0/quote` (dry quotes need no auth; quote response `{quote:{amountIn,amountInFormatted,amountInUsd,minAmountIn,amountOut,amountOutFormatted,amountOutUsd,minAmountOut,timeEstimate,refundFee,withdrawFee}, quoteRequest, signature, timestamp, correlationId}`; assetId format `nep141:eth-0xa0b8....omft.near`). Public RPCs: `https://ethereum-rpc.publicnode.com`, `https://base-rpc.publicnode.com`, `https://arbitrum-one-rpc.publicnode.com`, `https://api.mainnet-beta.solana.com`, `https://rpc.mainnet.near.org`. Candles: Coinbase Exchange `https://api.exchange.coinbase.com/products/<PRODUCT>/candles?granularity=<sec>` (returns `[[time,low,high,open,close,volume],...]` newest first; Binance is geo-blocked from this machine, do not use it). Kraken `https://api.kraken.com/0/public/OHLC` is the fallback source behind the same interface.

## HTTP API contract (server.ts implements, mcp.ts and ui consume)

Browser routes (never called by mcp.ts):
- `GET /` and static `ui/*`
- `GET /api/state` -> `{ledger, composition, cost, policy, proposals, mode, agents:{connected:number}}`
- `GET /api/candles?product=BTC-USD&granularity=60&limit=120` -> `Candle[]`
- `GET /api/log?limit=200` -> `LogEvent[]` newest first
- `GET /api/session` -> `{token}` (random per-boot browser token; minting is audit-logged)
- `POST /api/approve` `{id, token}`; `POST /api/refuse` `{id, token}`; `POST /api/kill` `{on, token}`. Wrong/missing token -> 403 + `approve_attempt_rejected` audit event. These three routes are the only mutating browser routes.
- `GET /api/events` -> SSE: `data: {"type":"state"}` (debounced change signal; client refetches /api/state) and `data: {"type":"log","event":{...}}` per log line.

MCP route (the only route mcp.ts calls):
- `POST /api/mcp` body `{op, ...}`:
  - `{op:'hello', client}` -> `{ok:true}` marks agent connected (45s heartbeat window)
  - `{op:'read', tool:'balances'|'composition'|'cost'|'policy_show'|'log_tail'|'candles'|'proposal_status', args}` -> tool result JSON
  - `{op:'propose', kind:'consolidate'|'policy_change', params}` -> `{id, status, verdict, simulation}`
  - Every op is audit-logged as `tool_call` before dispatch.

### Task D: Policy engine and proposals (THE PRODUCT)

**Files:** Create `src/policy/engine.ts`, `src/proposals.ts`, `tests/unit/engine.test.ts`, `tests/unit/proposals.test.ts`

**Interfaces:**
- Consumes: types only for engine (pure). Proposals consume `Audit`, `Store`, `Ledger`, `classify`, `Quoter`, `Signer`, `loadPolicy/savePolicy`, `renderSentences` (Tasks A/B/C signatures above).
- Produces:
  - `engine.ts`: `export type EngineCtx = { policy: Policy | null; composition: CompositionView; ledger: LedgerSnapshot; sessionSpentUsd: number; selfAddresses: string[] }` and `export function evaluate(draft: WriteDraft, ctx: EngineCtx): Verdict`.
  - `proposals.ts`: `export function createProposalService(deps: { cfg: AppConfig; audit: Audit; store: Store; ledger: Ledger; riskRows: RiskRow[]; quoter: Quoter; signer: Signer; dataDir: string; onChange?: () => void }): ProposalService` exactly per `types.ts`.

**Engine rule order** (first refusal wins; reasons accumulate; rule ids exact):
1. `ctx.policy === null` -> refuse `policy_unreadable`
2. `policy.killSwitch` -> refuse `kill_switch`
3. `kind === 'policy_change'`: patch must be structurally valid (zod: only known keys of `PolicyPatch`, numbers finite and `>= 0`, shares `0..1`) else refuse `invalid_patch`; any attempt to touch `killSwitch`/`version`/`sentences` at top level refuse `kill_switch_not_patchable`; otherwise ALWAYS `needs_approval` with reason `policy changes always require a human click`. Never `allow`.
4. Fund moves (`consolidate`/`transfer`): every leg must have a non-null `quote` (simulation), else refuse `simulation_required`.
5. Any leg `to` not in `selfAddresses` (lowercased) and not in `destinationAllowlist` -> refuse `destination_not_allowed`.
6. Any leg `amountUsd > maxPerTransactionUsd` -> refuse `max_per_transaction`.
7. `sessionSpentUsd + totalUsd > maxPerSessionUsd` -> refuse `max_per_session`.
8. Target symbol's issuer (via composition rows or risk rows) in `forbiddenIssuers` -> refuse `forbidden_issuer`.
9. Post-state composition (recompute from a cloned snapshot with each leg applied: from-chain minus amount, to-chain plus `quote.amountOut`): any issuer share > its cap (`maxIssuerShare[issuer] ?? maxIssuerShare.default ?? 1`) -> refuse `max_issuer_share`; freezable share > `maxFreezableShare` -> refuse `max_freezable_share`; any touched chain's post-gas native usd < `minNativeGasUsd[chain]` -> refuse `min_native_gas`. (Post-state computation is a helper inside engine.ts: `export function applyLegs(snapshot: LedgerSnapshot, legs: TransferLeg[]): LedgerSnapshot` cloning, never mutating.)
10. `totalUsd > humanClickAboveUsd` -> `needs_approval`.
11. Else `allow`.

**Proposal flow (`proposeConsolidate`):** plan legs = every stable holding of `symbol` on `fromChains ?? all chains except toChain` with `usd >= dust threshold` (same dust rule as cost.ts), capped by `maxTotalUsd`; recipient = self address on toChain (config/demo accounts; if none, the proposal is created already `policy_refused` with verdict refuse `destination_not_allowed`); quote each leg via `quoter.quoteLeg` (a throw -> `SimulationResult {ok:false, error: raw message}` -> verdict refuse `simulation_required` with the solver error verbatim in reasons); simulation summary lines like `"eth -> base: 9,200.00 USDT, fee $0.94, ~8s"` plus post-composition deltas; evaluate; persist with status `pending` (needs_approval), `policy_refused` (refuse), or for `allow`: execute immediately. Execution: demo mode -> `ledger.applyDemoTransfer(leg)` per leg + status `executed`; live mode -> `signer.ready === false` -> status `failed`, result detail = signer.describe() (the auth step), audit `execution_failed`. Audit events at every transition (`proposal_created`, `policy_refused`, `approved`, `refused`, `executed`, `execution_failed`).
**`proposePolicyChange`:** simulation = `{ok:true, summary, policyDiff:{before: current sentences, after: renderSentences(patched)}}`; verdict per engine; on human approve: apply patch (deep-merge onto current policy, bump `version`, append `sentence` to `sentences`), `savePolicy`, audit `policy_changed`.
**`approve(id)`/`refuse(id)`:** only valid from status `pending`; approve sets `approved` then runs execution (fund moves) or applies patch (policy change) then final status; refuse sets `refused` with `decidedBy:'human'`. Both audit-logged. `sessionSpentUsd()` sums `executed` fund-moving proposals with `decidedAt` (or createdAt) within 24h from store.
