# Ready for people: lessons

One line per lesson: what bit, and the rule. Only what the repo, the vault note and the builder prompt do not already record. Teammates append; the lead reads it before every new brief.

- [node F] loadConfig (src/config.ts) DROPS the `driver` block, so a demo backend's `config.json` cannot point the window's chat at a stand-in agent: it spawns whatever `claude` src/driver.ts finds ($HOME/.local/bin/claude first). To keep the real Claude Code and its subscription out of a screenshot run, give the backend a scratch HOME with the scripted agent at $HOME/.local/bin/claude. (dead `driver.claudeBin` also noted in the vault Gotchas.)
- [node F] The ending notice (src/http/ended.ts) fires on the terminal WRITE, so a reply read after waitStage(confirmed) already contains the ending: wait for the ending by TURN COUNT (a fresh turn after the decision turn), never by a text diff against a reply the terminal write already changed.
- [node F] The ended notice is dropped when the agent already read the terminal stage (seen() on (id, stage)). A synchronous refusal's "one sentence" is therefore the reply said IN the propose turn, not a separate notice; only an async settlement (a click, a stall) gets a fresh ending turn.
- [node F] A seeded proposal in a transient in-flight status does not survive boot: reconcileOnBoot rewrites awaiting_touch to pending, approved (no hold) and executing to needs_reconciliation, and approved+heldSince to failed (expireHold). So Touch ID, signing, submitting and active-hold cards cannot be produced by seeding in demo; they are only reachable live, which a software-wallet demo never walks through.
- [node F] The onboarding words screen's Continue stays inert until the "I have saved these" checkbox is ticked; a headless flow must check it before advancing.

- [2026-09-20] The automation Brave is one daemon for every agent on this Mac: a browser-use call without switch_tab lands in whichever tab is active, and one reviewer finished another reviewer's onboarding walk (port 4215) by accident. Rule: every browser-driving brief says switch_tab to your own tab (by URL) before every call, and one backend port per agent.
- [2026-09-20] browser-use supports a per-agent daemon: BU_NAME=<name> gives an agent its own browser session, so trusted clicks from a peer never land on its tab. Every browser-driving brief should set BU_NAME to the agent's name (the C reviewer redid its walk clean that way).
- (A) The nonce the verifier reads today is versioned (magic 5628f6c6, version, the contract's 4-byte salt, an expiry, 15 random bytes); the spec's 32 random bytes are the legacy shape the contract README announces as ending. Read the vendor's contract README for the nonce layout before building any intent, and read current_salt before signing.
- (A) The public solver relay quotes a narrower asset set than 1Click (no wNEAR either way on 2026-09-20 while USDC to USDT, ETH and arb USDC quote): probe the pair read-only (scripts/relay-probe.ts) before a live proof; a 1Click pair is not a relay pair until it quotes.
- [C] `hermes mcp add` (0.21.3) stops at "Enable all N tools? [Y/n/select]" and answers end of file with Cancelled; a second add asks "overwrite?" first and eats the one answer. Rule: remove the old entry, then add with `Y\n` on stdin, and measure a vendor's `mcp add` for prompts before calling it from the app.
- [C] A child spawned for a probe must get stdin `ignore`, not a pipe: an agent CLI pointed at an empty config home stops to ask a first-run question and sits on the open pipe until the cap kills it (hermes --version took the whole 2.5 s cap that way).
- [C] tests/unit/ui-links.test.ts refuses any `href` write in ui/ outside core/links.js, so a screen cannot inject its own stylesheet link; a new ui/design/*.css goes in index.html.
- [C] PHOSPHOR_DATA_DIR under the worktree's state/ is refused in demo mode (config.ts derives keys.json from it and refuses a key inside the working copy); a demo backend's data dir has to sit outside the checkout, the session scratchpad works.
- [C2] A flag that means "this was already so" must be read before the request writes the same state: agent-pick wrote the pick, then the check read it back as an earlier pick and said "no longer on this Mac" to a fresh click. Rule: check, then write.
- [C2] Two readers of one env contract drift on names when one cannot import the other: config.ts read PHOSPHOR_PORT then ACC_PORT, the thin proxy read ACC_PORT alone, and every registration the app wrote dialled 4177. Rule: mirror the helper with the same names in the same order, and pin it with a test that spawns the proxy against a stub app.
- [B] PHOSPHOR_DATA_DIR under the worktree's state/ refuses to boot: src/config.ts demands the keys path outside the repo. Rule: add PHOSPHOR_KEYS=<scratchpad>/<node>-keys.json beside it.
- [B] Driving a demo backend by hand: POST /api/mcp {op:'propose', kind:'hl_withdraw', params:{amount}, session, secret} with the seat secret from <dataDir>/agent.secret; the click is POST /api/approve {id, token}; after a reboot the demo wallet is locked, POST /api/wallet/unlock {token, password} first. The seat secret and the window token never go in a commit.
- [B] toAmountString(a + b) throws on a float sum (8.209399 + 1 has a seventh decimal) and a refusal that computed its own sentence read as "rail threw". Rule: the signing formatter formats signed amounts only; a sentence's figure goes through toFixed and a trailing-zero trim.
- [B] The first status poll runs the instant the submit answers, so "Deposit seen" reaches the card as soon as 1Click sees the money; the demo's stage clock is STAGE_MS times PHOSPHOR_DEMO_STAGE_SCALE, so a harness that wants a stage on screen for a screenshot sets the scale, never a sleep.
- [B] 1Click's own docs (docs.near-intents.org, 1click-api/hyperliquid.md) list sendAsset as a supported way in ("Spot or perp"), spotSend as spot only and usdSend as partial with an extra 1 USDC deducted; the activation fee is Hyperliquid's and applies to the first transaction into a new account whatever the action (activation-gas-fee page). Rule: the 1 USDC stays on the card for every action.
- [B2] runRail's final persist spreads the pre-hook `executing` row, so a field the evidence hook wrote (evidence, preflight, now pocket) reaches the terminal row only where the executor re-reads it by name or the rail's answer carries it again. Rule: a rail that tells the executor something early repeats it on every answer that should keep it.
- [B2] `npm run typecheck` covers scripts/scratch/ even though git ignores it: an unused variable in a reviewer's scratch script fails the gate. Rule: keep scratch scripts compiling or move them out of scripts/ before the count.
- [H] A demo row wears needs_reconciliation while it is settling: the credit read that closes it comes one CREDIT_MS beat later. A wait loop that counted that status as an ending read all five swaps as stuck one second before they confirmed. Rule: wait on executed, failed or refused (or settledAt), never on needs_reconciliation.
- [H] Under a loaded machine (peer suites running) tests/unit/driver-memory, driver-prompt and driver-reason time out at their 5 s caps and fail 3 of 3219; alone they pass 14/14. Rerun those three by themselves before calling a full-suite count red.
- config.json's `driver.claudeBin` never reaches the app's own conversations: src/config.ts loadConfig drops the driver block, so the chat child is whatever `resolveClaudeBin` finds under $HOME, the real `claude` on this Mac. A proof or an eval that wants the scripted agent in the window sets HOME to a stage dir with `.local/bin/claude` pointing at tests/eval/agent.ts (scripts/card-proof.ts does); scripts/eval.ts thinks its idle-agent config does this and it does not.
- A card that is rebuilt on every state frame cannot fade and cannot keep a fold: build once, keep a `paint(data)` on the node, and let the reconciler call it. The fade itself is two keyframe names alternated on an attribute, because a changed attribute value restarts nothing and a changed animation-name does.
- A stage line whose copy sits beside its clock jumps the card 18 px whenever the copy wraps; give the copy its own two lines of room and the clock its own line, and hold the clock line's room with visibility rather than display when it has nothing to say.
- Flex items trim the leading space of their text: "25s" + " end to end" printed as "25send to end". Use gap on the row, never a leading space in a span.
- Playwright's element screenshot waits for the element to be "stable" and "visible" by its own rules; a card whose clock ticks under a sticky column header never is. Clip the viewport by the element's box instead.
- [E] A dock whose answer sits in its scrolling body needs the column's height, not a share of it: a percentage cap plus a shrinkable flex item (flex 0 1 auto) hands the height to the transcript and put No and Yes 137 px under the fold at a 400 px column. Cap it against the column (calc(100% - 120px)) and make it flex 0 0 auto; measure the buttons' rects in a real browser, a source test cannot see this.
- [E] Grid rows follow the items that are placed: hiding the split handle (display none) in the stacked stage takes a track with it, so three rows for two items put the conversation on the 0 px row. Write the rows for the items that are left.
- [E] The theme tool holds --down to the 3:1 mark floor and the window sets words in it (Turn off, Failed, the amount that left): a set_theme patch the server accepts can put every red word under the 4.5:1 text floor. The floor is the server's to raise (src/view/theme.ts), not a stylesheet's to hide.
- [E] The button inventory's sheet forces hover, active and focus-visible through CSS.forcePseudoState on playwright-core's CDP session (the 1.63 copy in ~/.npm/_npx/705bc6b22212b352 drives the cached chromium_headless_shell-1243); fifty families, every state, one page, no clicking.
- [G] `git rev-list --objects --all` in a worktree sees every sibling branch, so `npm run sweep` on one node's branch fails on a value a peer committed on theirs (node B's research doc, four signature halves): allowlist the peer's public values in sweep.ts or the sweep is red for everyone until merge.
- [G] tests/unit/docs.test.ts pins the changelog's first "## " heading to package.json, so a "version that ships next" heading in the changelog is red until the lead bumps package.json, Cargo.toml and tauri.conf.json in the same merge.
- [G] gitleaks 8.30's generic-api-key rule fires on `tokenId: 'nep141:<64 hex>'` and on an env var NAME constant: 176 hits on this tree, zero secrets. The repo's own sweep is the gate that means something; gitleaks needs a .gitleaks.toml allowlist before its exit code can.
- [G] The site's /docs is rebuilt by a separate push of the site repo, not by the app release: on 2026-09-20 the download served 0.7.0 while the live docs and changelog still said 0.6.0 and "Not tagged". A release is not done until the site docs are rebuilt.
